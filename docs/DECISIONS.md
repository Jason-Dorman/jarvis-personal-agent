## Decided

- **"Good morning" gets "Good morning, Mr. Dorman."** PO's request. A bare greeting (morning, afternoon, or evening, with or without "hey Jarvis") is answered instantly in `Brain.ask` without calling Claude, mirroring the greeting the PO used. It's logged to `conversation` like any turn. A greeting with a question goes to Claude, and the prompt says to open with the greeting and the name. The name is `address_as` in `config.yaml`, not hardcoded. *Why instant:* it needs no data, and a round trip would add about 1.5 s. It measured 0.02 s. *(2026-10-30)*
- **Latency: Sonnet on the Agent SDK at effort medium stays. The first-word miss is written down, not chased.** PO's call (2026-10-30): no switch to Haiku, effort low, or the plain API. Measured on five voice turns (one tool each): stopped talking → first word ("Checking.") median 2.97 s against the 2.5 s target, and → answer start median 4.8 s. The breakdown is endpointing 0.73 s, speech-to-text 0.30 s, the first round trip to Claude about 1.6 s, then the tool and the second round trip. Two findings: (1) after a tool result, the API sends the whole reply in one burst instead of streaming it. Confirmed with a raw Messages API call outside the Agent SDK, so it's upstream and not ours to fix. (2) Effort `low` was no faster in a probe (tool call at 1.70 s vs 1.50 s). The 0.7 s silence timeout stays: 0.5 s would save 0.2 s, still miss, and cut people off mid-pause. *(2026-10-30)*
- **"Checking." plays as soon as the first tool call of a turn starts,** always the same word (PO: "just 'checking' is fine"). This replaces the old rule (a tool running 0.8 s). *Why:* tools are fast (median 0.22 s), so the old rule almost never fired, and the silence was the second round trip to Claude. Questions that use no tool still stay quiet. *(2026-10-30)*
- **Answers can run up to 5 sentences with context.** PO is fine with more detail. `brain.max_spoken_sentences: 5`, and the prompt asks for the answer first, then the trend, comparison, driver, or what to watch. The context must come from tool results, with no guessing at causes. The prompt calls it a hard limit, because "at most 3" drifted to 4 and "at most 5" drifted to 6 or 7. *(2026-10-30)*
- **Misheard questions:** the prompt tells the brain the text came from speech-to-text. If a word looks misheard but the meaning is clear, it answers and names its guess in a few words. Otherwise it asks in one short sentence. *(2026-10-30)*
- **Brief length on busy days** (was open question 6): it can run to about two minutes, around 300 words. *Why:* PO is fine with more detail. *(2026-10-30)*
- **Barge-in has three modes (`barge_in`), default `wake_word`.** PO's call. `wake_word`: "Hey Jarvis" interrupts, which works on laptop speakers. `voice`: any steady speech while Jarvis talks (0.32 s) interrupts, which needs headphones. `off` (nothing interrupts). In the first two modes push-to-talk interrupts too. Tested on speakers: "Hey Jarvis" during the brief cut it off and the next question was answered. `voice` on speakers looped, with Jarvis interrupting itself on its own echo about 10 times in a row. *(2026-10-30)*
- **No software echo canceller** (was open question 2). The wake-word mode works on speakers without one. *(2026-10-30)*
- **Echo guard for `barge_in: voice`:** if the transcript after a voice barge-in is mostly Jarvis's own recent words (60% of at least 3 content words), it's dropped, the session switches to `wake_word`, and the terminal says why. Shorter follow-ups ("what about ETH?") aren't judged, so they can't be dropped by mistake. *Why:* on speakers, `voice` otherwise loops and keeps calling Claude. *(2026-10-30)*
- **Push-to-talk while Jarvis is busy now interrupts it.** This replaces "presses made while busy are dropped". Typed questions still wait their turn. *Why:* holding the talk key mid-answer means "stop, I want to say something". *(2026-10-30)*
- **After a wake-word or push-to-talk barge-in, the next 0.15 s of mic audio is dropped.** *Why:* the first barge-in test heard "Thank you, Q. What's Bitcoin?". The "Q" was Jarvis's own "QQQ" still coming out of the speakers. *(2026-10-30)*
- **The cut-off reply winds down in the background.** The SDK gets `interrupt()`, its remaining messages are drained, and the next `ask` waits for that. Its late tool events are logged but kept off the HUD. If the wind-down takes over 5 s, Jarvis reconnects with a fresh session (losing the conversation so far) rather than risk a stuck one. *(2026-10-30)*
- **Global push-to-talk is Ctrl+Alt+Space** (was open question 1), through Windows RegisterHotKey. PO's call. RegisterHotKey reports only that combo (no keyboard hook). Release is detected by polling the main key. Not Ctrl+Space, because that's VS Code's autocomplete. If the combo is taken, startup says so and push-to-talk stays HUD-only. Tested with injected key events: holding the combo mid-answer cut it off, and the question asked during the hold was answered. *(2026-10-30)*
- **Warm the data on wake.** The wake word or push-to-talk starts a background refresh of the stablecoin list and the watchlist quotes, so the tool calls a few seconds later hit the cache. At most one runs at a time, and errors are only logged. *Why:* peg lookups took 0.35 to 0.87 s cold, and you're still talking while this runs. *(2026-10-30)*
- **Speech-to-text stays `small.en`, with level normalization added.** A self-test (Piper's voice through the laptop speakers into the mic, peaks around −30 dBFS) scored vocab words at 77% with `small.en` and 77% with `medium.en`. Decoding the same captures several ways: normalizing the level to −6 dBFS peak (at most 20× gain) went from 81% to 85%. Adding the previous question to whisper's prompt didn't help on its own, and it pulled "USDT" toward "USDC" right after a USDC question. Real follow-ups switch coins, so it's left out. The weak spots are USDT vs USDC and the short "And Tether?". This voice-from-a-speaker test is harsher than a person at the mic. The 95% target needs `checks vocab` run with the PO's own voice. *(2026-10-30)*
- **Wake word → chime is about 0 ms in process,** but openWakeWord fires 0.5 to 0.9 s after "Hey Jarvis" ends (measured with Piper's voice). That delay is how the model scores a sliding window, so the spec's 0.3 s can't be met by tuning our code. A higher `sensitivity` makes it fire a little earlier, at the cost of more false wakes. *(2026-10-30)*
- **Wake sensitivity stays 0.5.** Zero false wakes in 23 min of a quiet room (stopped early, since a quiet room at night isn't the hard case) and in 4.2 min of continuous finance speech played through the speakers. The highest score was 0.01 against the 0.5 threshold. A daytime hour with real room noise is still open for the PO. *(2026-10-30)*
- **Per-turn timing is recorded** to the log and a `turn_timings` table (source, question, model, tool count, interrupted, spans as JSON). `python -m jarvis.checks timings` summarizes it. "Checking." counts as the first spoken word, and the answer start is reported separately. *(2026-10-30)*
- **The spec 10 checks are one command,** `python -m jarvis.checks` with `timings`, `vocab`, and `wake`, in place of separate scripts. *(2026-10-30)*

- **CUDA comes from pip, not a system install.** `nvidia-cublas-cu12` and `nvidia-cudnn-cu12` are dependencies (not on macOS). Whisper loads and warms up on the main thread at startup, then falls back to CPU int8 if CUDA fails. Beam size is 5 on the GPU and 1 on the CPU. *Why:* nothing to install by hand, and native DLLs loading in worker threads froze the app before (yfinance). *(2026-10-29)*
- **Silero VAD is the v6 ONNX file that ships inside faster-whisper,** run on onnxruntime. *Why:* the official Silero package pulls in PyTorch (about 2 GB) for one small model. *(2026-10-29)*
- **Audio goes through WASAPI with auto-convert.** The mic opens at 16 kHz and the speakers at Piper's 22.05 kHz, even though the hardware runs at 48 kHz. Devices are the Windows defaults unless `audio.input_device` / `audio.output_device` name one. *(2026-10-29)*
- **`wake_word.sensitivity` means "higher wakes more easily".** The detection threshold is `1 - sensitivity`, so the default 0.5 is openWakeWord's recommended 0.5. *(2026-10-29)*
- **Spoken cleanup (`speakable()`) spells tickers out letter by letter,** except words people say (HYPE, COIN, SOL, and a few English words in caps). It also rewrites `$` amounts, signed percents, and shorthand units. Captions keep the original text, so panel key words still match. *Why:* a Piper → whisper round trip showed "USDC" spoken as "Husk", "USDT" as "US", and "$77,000" garbled. *(2026-10-29)*
- *(Replaced 2026-10-30, see above.)* **"Checking." plays when a tool call has run for 0.8 s with nothing said yet,** once per turn. *Why:* a fixed timer would also fire on slow answers that use no tool, which sounds odd. *(2026-10-29)*
- **Partial transcripts only on the GPU.** On CPU, a re-transcription every 0.8 s would slow the final one. *(2026-10-29)*
- **Whisper's silence hallucinations are dropped,** including a bare "thank you". *Why:* whisper often "hears" these in noise. The cost is that thanking Jarvis gets no reply. *(2026-10-29)*
- **Turn taking:** typed questions made while Jarvis is busy wait their turn. *(Replaced 2026-10-30: push-to-talk while busy now interrupts.)* ~~Push-to-talk presses made while it's busy are dropped.~~ Typing or pressing push-to-talk while it's listening takes over from the voice capture. *(2026-10-29)*
- **Added `Tether` and `watchlist` to the default `stt.vocab`.** *Why:* the spec's own follow-up is "and Tether?", and whisper wrote "watch list". *(2026-10-29)*
- **The voice state machine lives in `jarvis/conversation.py`,** and `main.py` only wires things up. The plan had it in `main.py`. *Why:* one job per file. *(2026-10-29)*

- **The brain runs at `effort: medium` by default,** set in `config.yaml` (`brain.effort`). *Why:* the spec puts accuracy first ("no made-up numbers"), and medium kept answers grounded in tool calls while staying near 3 s. Chunk 3 kept it (see the latency decision above). *(2026-10-29)*
- **Model names in config map to exact IDs** (`sonnet` → `claude-sonnet-5-5`, `opus` → `claude-opus-5-5`, `haiku` → `claude-haiku-5-5`) in `jarvis/config.py`, so a CLI alias can't drift to a different model. "Think hard" and "deep dive" switch to the deep model for that one question only. *(2026-10-29)*
- **The brain session is isolated from this machine's Claude setup:** no `CLAUDE.md`, no user settings, no skills or subagents (`setting_sources=[]`, `tools=[]`), and prompts aren't expanded (`verbatim_prompts`). Verified at startup: the CLI lists exactly the 11 Jarvis MCP tools. *Why:* the read-only rule, and the dev `CLAUDE.md` in this repo is not Jarvis's personality. *(2026-10-29)*
- **Panel keys reach the brain through the post-tool hook,** as a short note added to each tool result ("Panels on screen: 'USDC peg' (say: usdc, usd coin)"). *Why:* the brain learns about a panel the moment it exists, and tools stay unaware of the HUD. *(2026-10-29)*
- **Peg rules:** only USD pegs are judged. `warn` at 0.5% off $1, `alert` at 2%. `list_peg_alerts` only reports coins with more than $1B supply, so tiny tokens don't cry wolf. When two coins share a symbol (there are several "USDS"), the bigger one wins. *(2026-10-29)*
- **Stock change is close to close (1 trading day); crypto change is rolling 24 hours.** Each result says which (`change_label`). Yahoo calls get a 10 s budget per request, then the symbol comes back as unavailable. *Why:* yfinance can hang. A missing number beats a stalled answer. *(2026-10-29)*
- **Saved notes:** theses go to `notes/theses.md` as a new `## heading` section with the date. Other thoughts go to `notes/inbox.md` as dated bullets. The brain chooses the heading. *(2026-10-29)*
- **In `--text` mode, `speech` events go out as each sentence is generated,** since there's no audio to sync to. Chunk 2 moves them to playback start. *(2026-10-29)*
- **`get_article_summary` only fetches public `http(s)` links,** never localhost or private addresses. *Why:* feed text could steer the model toward a local URL. *(2026-10-29)*
- **Logs go to `logs/jarvis.log`,** not the terminal, so the REPL stays readable. *(2026-10-29)*
- **Config is pydantic, strict.** `jarvis/config.py` loads `config.yaml` into frozen pydantic models and rejects unknown keys, so typos fail at startup. Added `theses_file` and `debug` keys next to the spec's list. Fixed data paths (`jarvis.db`, `notes/`, `briefs/`, `logs/`) are constants in `config.py`, not settings. *Why:* pydantic already ships with FastAPI, and strict loading catches mistakes early. *(2026-10-29)*
- **The repo is a uv "virtual" project (`package = false`).** Everything runs from the repo root, so `jarvis`, `tools`, and `hud` import as top-level packages (`from hud.server import hud`). pytest gets the root on its path. *Why:* nothing to build or install for a personal app. *(2026-10-29)*
- **Memory schema.** `price_snapshots(ts, symbol, price, change_pct, source)`, `tool_calls(ts, tool, fn, inputs JSON, outputs JSON, error, duration_ms)`, `conversation(ts, session_id, role, text, model)`. All timestamps are ISO-8601 UTC. *Why:* covers spec 6.8 and the Chunk 1 logging needs, nothing more. *(2026-10-29)*
- **Jarvis runs on native Windows, not WSL2.** The PO moved the project off WSL2. Audio uses Windows devices directly through `sounddevice`, so the WSLg PulseAudio bridge risk is gone. *Why:* PO's call. *(2026-10-29)*
- **Morning brief is on demand only.** It runs when asked ("hey Jarvis, give me my morning brief", or typed). No scheduler, no 7am run. Asking twice in one day replaces that day's file. *Why:* PO preference. *(2026-10-29)*
- **Brief data comes from one `brief.get_brief_data()` tool call,** not five separate tool calls chosen by the model. *Why:* one round trip means the brief starts faster, and the content is the same every time. The tool reuses the other tools' plain functions. *(2026-10-29)*
- **Tools are in-process MCP servers** (Agent SDK). Each tool is still its own server, but there are no extra processes. *Why:* simpler to run and debug. Keeps the spec's "one server per tool" shape. *(2026-10-29)*
- **HUD events come from SDK pre/post tool hooks,** not from inside the tools. *Why:* tools stay unaware of the screen (low coupling). Cards are built from tool data, per spec 15.6. *(2026-10-29)*
- **Agent SDK built-in tools are all turned off.** Only Jarvis's MCP tools are allowed. *Why:* this enforces the read-only safety rule. *(2026-10-29)*
- **Big build chunks.** The work is split into four large chunks, not small slices. *Why:* fun personal project, speed over ceremony, fix as we go. *(2026-10-29)*

## Open questions for the PO

Each one has a default. Work proceeds on the default unless the PO says otherwise.

1. **Watchlist and theses file format.** *Default:* `watchlist.md` is one symbol per line as `- BTC` or `- SPY (stock)`. `theses.md` uses one `## heading` per thesis with free text under it. Chunk 0 seeded both files this way, with a starter watchlist (BTC, ETH, SOL, HYPE, SPY, QQQ, COIN) and one example thesis. Swap in your own.
2. **Price data keys.** *Default:* CoinGecko's free/demo key if one is provided in `.env`, no key otherwise. Is there a paid key or a preferred source?
3. **Brief length when nothing happened.** *Default:* skip quiet sections in a single line ("All pegs normal. Watchlist quiet.") even if the brief ends up under 60 s.
